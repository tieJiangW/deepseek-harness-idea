# DeepSeek Harness for IntelliJ IDEA — v0.2.4

## English

### Highlights

- **Configuration is now shared across projects.** Models, providers, API keys, agent presets and personal skills
  live in one shared config home, so configuring them once applies to every project. Sessions, workspaces and
  attachments stay isolated per project.
- **This fixes a real data-loss bug:** custom models, API keys and agent presets used to disappear silently after
  restarting the IDE.
- **"Send selection" and "Explain log" work again on dsh 0.1.5** (Lexical composer), and no longer stack duplicate
  file references when triggered twice.
- **macOS verified** end-to-end on Apple Silicon.

### What was wrong, and how it is fixed

Three separate problems produced the "configuration disappears" symptom:

1. `DshHomeManager.ensureHome` copied the global config over the per-project config on every start
   (`copyGlobalConfigTo`), while dsh reads its configuration from `$DSH_HOME` — so anything dsh wrote during a session
   (a new model, a language switch) was wiped on the next start.
2. The patch section intended to redirect that configuration to a shared path used the `- $settings:` form, which dsh
   rejects with `patch: id is required for non-insert patches`, silently dropping the whole patch.
3. The caller never passed the shared config root to the patch generator, so even a valid patch would not have been
   emitted.

The fix deletes the copy step, emits the correct patch rows
(`- id: settings` / `- id: credentials` / `- id: agent-presets` / `- id: skill-filesystem`), and keeps the user-level
config surface shared while the data surface stays per project. Existing per-project config files are **merged** into
the shared document (text-level namespace and `refs`/`records` merge, comments preserved) and the originals are backed
up under `migrated/` — nothing is deleted.

The MCP bridge script is now a single shared copy deployed inside the dsh installation tree, so the per-project
`node_modules` link is gone (Node's ESM resolution does not traverse directory links).

For dsh 0.1.5's Lexical (`contenteditable`) composer, the injection was rewritten: it writes through `insertText`,
reads back through `[data-lexical-text]` nodes, retries when the first write has no effect, and no longer stacks a
second write mechanism (which had double-inserted the reference).

### Assets

- `deepseek-harness-idea-0.2.4.zip` — plugin (thin: the runtime downloads on first use, SHA-256 verified).
- `runtime-<os>-<arch>.zip` + `.sha256` — prebuilt runtimes for Windows x64, macOS arm64/x64, Linux x64/arm64.
  Use these to stay offline: *Settings → Tools → DeepSeek Harness → Choose local runtime zip…*

### Compatibility

IntelliJ IDEA 2024.1 – 2026.2 (`since-build=241`, `until-build=262.*`). dsh 0.1.5-rc.2 (Node.js 22.23.2).

## 中文

### 重点

- **配置改为跨项目共享**：模型、供应商、API Key、Agent 预设与个人技能统一存放于共享配置目录，配置一次即对所有
  项目生效；会话、工作区与附件仍按项目隔离。
- **修复了一个真实的数据丢失问题**：此前自定义模型、API Key、Agent 预设会在重启 IDE 后静默消失。
- **"发送选中代码"与"日志一键解释"在 dsh 0.1.5 上恢复可用**（Lexical 输入框），并修复了重复触发时文件引用重复叠加。
- **macOS 已在 Apple Silicon 上完成端到端验证**。

### 问题根因与修复

"配置消失"由三个独立问题叠加造成：

1. `DshHomeManager.ensureHome` 每次启动都把全局配置**覆盖**到项目配置（`copyGlobalConfigTo`），而 dsh 实际从
   `$DSH_HOME` 读取配置 —— 于是会话期间的改动（新增模型、切换语言）会在下次启动被抹掉。
2. 用于把配置重定向到共享路径的 patch 使用了 `- $settings:` 形式，被 dsh 以
   `patch: id is required for non-insert patches` 拒绝，整条 patch 被丢弃。
3. 调用方从未把共享配置根传给 patch 生成器，即使语法正确也不会生成该段。

修复：删除复制步骤；改用正确的 patch 行（`- id: settings` / `- id: credentials` / `- id: agent-presets` /
`- id: skill-filesystem`）；用户级配置面共享、数据面仍按项目隔离。既有的项目级配置文件会**合并**进共享文档
（文本级 namespace 与 `refs`/`records` 合并，保留注释），原文件备份到 `migrated/`，**绝不删除**。

MCP 桥接脚本改为全局唯一一份、部署在 dsh 安装树内，因此不再需要每个项目创建 `node_modules` 链接
（Node 的 ESM 解析不会穿透目录链接）。

针对 dsh 0.1.5 的 Lexical（`contenteditable`）输入框重写了注入：用 `insertText` 写入、通过
`[data-lexical-text]` 节点回读、首写无效则重试，并移除了会**重复写入**的第二种写入机制（此前会导致引用叠加两份）。
