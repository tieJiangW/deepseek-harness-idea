# DeepSeek Harness for IntelliJ IDEA — v0.2.6

> 本版本只做一件事：把内置运行时升级到 **DeepSeek Harness 0.2.1-rc.2**，并适配其破坏性变更。
> This release upgrades the embedded runtime to **DeepSeek Harness 0.2.1-rc.2** and adapts to its breaking changes.

## English

### Highlights

- **Runtime upgraded to dsh 0.2.1-rc.2** (Node.js 22.23.2). The launch command, browser-auth token (`?token=` →
  cookie), workspace RPC, storage layout and composer contracts did **not** change and were re-verified against the
  real runtime (boot, health check, workspace registration, MCP tool sync).
- **IDE MCP tools keep working.** dsh 0.2.1 no longer ships `@modelcontextprotocol/sdk` / `express` (its MCP client
  moved to `@modelcontextprotocol/client`), which would have silently disabled every `ide_*` tool. The runtime build
  now installs both packages and asserts they resolve, so a broken runtime cannot ship.
- **Configuration is still shared across projects.** dsh 0.2.1 moved user settings out of `settings.yaml` into the
  profile's `cordis.patch.yml`. Existing settings are migrated once (`settings.yaml` is staged for dsh's importer and
  backed up as `settings.yaml.imported`), and because `profiles/` is already shared, one import covers every project.
  API keys and personal skills continue to be redirected to the shared config home.
- **Agent presets and personal skills.** Presets are now declarative rows inside the shared profile (so they follow
  the shared profile automatically). The shared personal-skills row is explicitly re-enabled, because dsh 0.2.1
  disables it in the web layer.
- **Clear plugin-install failures.** dsh 0.2.1 checks plugin compatibility (`engines.dsh`) and can refuse a package.
  The plugin now surfaces the exact `allow-version … --accept-risk` command and the dsh diagnostics log path instead
  of a bare "command failed".
- **Installing from dsh's own plugin market now works.** dsh 0.2.1 ships a Plugins page in the Web UI that runs
  whatever `pnpm` it finds on `PATH`, while this plugin's DSH Plugins page uses its own private pnpm. Mixing pnpm 9
  and pnpm 11 on the same `node_modules` makes pnpm refuse to touch it
  (`ERR_PNPM_VIRTUAL_STORE_DIR_MAX_LENGTH_DIFF`, then `ERR_PNPM_PUBLIC_HOIST_PATTERN_DIFF`). The dsh child process now
  gets the plugin's private pnpm prepended to its `PATH`, so both entry points use one pnpm; the pnpm shim is also
  rewritten on every start so it never points at a removed runtime.

### Breaking changes handled

| dsh 0.2.1 change | Effect if unhandled | Fix in v0.2.6 |
|---|---|---|
| Install tree no longer has `@modelcontextprotocol/sdk` / `express` | `mcp-ide-server.mjs` cannot start → all `ide_*` tools gone, no error in the UI | Runtime build installs both and asserts four specifiers resolve |
| `settings` row is now `@deepseek-ai/dsh-settings` (no Config); `settings.yaml` replaced by the profile patch | Shared settings silently ignored (model/language changes appear lost) | Stop patching that row; stage `settings.yaml` for dsh's one-time importer |
| `agent-presets` row renamed to `agent-preset-registry` (Config only `default`/`selectedDefault`) | dsh warns and skips the patch; shared preset root ignored | Stop patching; presets live in the shared profile |
| `skill-filesystem` is `disabled: true` in the web layer | Shared personal skills never registered | Patch adds `disabled: false` |
| Welcome notice version bumped to `2026-09-28.1` | Onboarding dialog could reappear | Constant updated; acknowledgement still pre-written |
| Web plugin market uses `PATH` pnpm while the plugin page uses its private pnpm | pnpm refuses the shared `node_modules` (`ERR_PNPM_VIRTUAL_STORE_DIR_MAX_LENGTH_DIFF`, then `..._PUBLIC_HOIST_PATTERN_DIFF`) | Private pnpm's shim is prepended to the dsh child `PATH` (and rewritten per start) |

### Upgrading

Install over v0.2.5 as usual. On first start the plugin downloads the new `0.2.1-rc.2` runtime (SHA-256 verified), runs
its existing settings/credentials migration, and stages the legacy settings document so dsh imports it into the shared
profile. Nothing is deleted; the old runtime directory stays on disk for a rollback.

> **Note on the settings import.** dsh imports each legacy section into the matching profile entry and validates it
> against that entry's schema. In our real-runtime check, `locale` and `ui-onboarding` imported cleanly, while a
> section whose content did not match the current schema was skipped and **left behind in
> `<DSH_HOME>/settings.yaml.imported`** (nothing is lost). If a custom model or provider does not show up after the
> upgrade, re-add it once in the Web UI (Settings → Models) — it will then be stored in the shared profile and apply to
> every project.

## 中文

### 本版重点

- **运行时升级到 dsh 0.2.1-rc.2**（Node.js 22.23.2）。启动命令、浏览器鉴权 token（`?token=` → cookie）、工作区 RPC、
  存储布局与 composer 契约**均未变化**，并已对真实运行时复验（启动、健康检查、工作区注册、MCP 工具同步）。
- **IDE 的 MCP 工具继续可用。** dsh 0.2.1 不再自带 `@modelcontextprotocol/sdk` / `express`（其 MCP 客户端改用
  `@modelcontextprotocol/client`），若不处理会让 7 个 `ide_*` 工具**静默全挂**。运行时构建现在显式安装这两个包并断言可解析，
  坏运行时无法被发布。
- **配置仍跨项目共享。** dsh 0.2.1 把用户设置从 `settings.yaml` 移到 profile 的 `cordis.patch.yml`。既有设置会一次性迁移
  （把 `settings.yaml` 放到 dsh 的导入位置，原文件留档为 `settings.yaml.imported`）；由于 `profiles/` 本就共享，
  导入一次即对所有项目生效。API Key 与个人技能继续指向共享配置目录。
- **Agent 预设与个人技能。** 预设改为共享 profile 内的声明式行（随共享 profile 自动共享）；共享个人技能行显式恢复启用
  —— dsh 0.2.1 在 web 层把它禁用了。
- **插件安装失败有明确指引。** dsh 0.2.1 会做 `engines.dsh` 兼容判定并拒绝不兼容的包；插件现在会给出可直接执行的
  `allow-version … --accept-risk` 命令与 dsh 诊断日志路径，而不是只报"命令失败"。
- **dsh 自带的 Web 插件市场现在可以正常安装。** dsh 0.2.1 的 Web「插件」页执行的是 `PATH` 上的 `pnpm`，而本插件的
  「DSH 插件」页用自己的私有 pnpm。9 与 11 两个大版本交替改动同一个 `node_modules` 时 pnpm 会拒绝操作
  （先报 `ERR_PNPM_VIRTUAL_STORE_DIR_MAX_LENGTH_DIFF`，钉住该项后又报 `ERR_PNPM_PUBLIC_HOIST_PATTERN_DIFF`）。
  现在启动 dsh 时把私有 pnpm 的 shim 目录**前置进 dsh 子进程 PATH**，两条入口用同一个 pnpm；shim 每次启动按
  **当前**运行时的 node 重写，不会再指向已删除的旧运行时。

### 已适配的破坏性变更

| dsh 0.2.1 变更 | 不处理会怎样 | v0.2.6 的处理 |
|---|---|---|
| 安装树不再有 `@modelcontextprotocol/sdk` / `express` | `mcp-ide-server.mjs` 起不来 → `ide_*` 工具全部消失（UI 无报错） | 运行时构建装入两个包并断言四个 specifier 可解析 |
| `settings` 行改为无 Config 的 `@deepseek-ai/dsh-settings`；`settings.yaml` 被 profile patch 取代 | 共享设置被静默忽略（表现为模型/语言改动"丢失"） | 不再 patch 该行；把 `settings.yaml` 放到 dsh 的一次性导入位置 |
| `agent-presets` 行改名为 `agent-preset-registry`（Config 只有 `default`/`selectedDefault`） | dsh 只 warn 并跳过 patch；共享预设根失效 | 不再 patch；预设放在共享 profile 内 |
| `skill-filesystem` 在 web 层 `disabled: true` | 共享个人技能不注册 | patch 追加 `disabled: false` |
| 欢迎页版本常量升到 `2026-09-28.1` | 内测声明可能再次弹出 | 同步常量；仍预写已确认版本 |
| Web 插件市场用 `PATH` 上的 pnpm，插件页用私有 pnpm | pnpm 拒绝同一个 `node_modules`（先 `ERR_PNPM_VIRTUAL_STORE_DIR_MAX_LENGTH_DIFF`，再 `..._PUBLIC_HOIST_PATTERN_DIFF`） | 私有 pnpm 的 shim 前置进 dsh 子进程 `PATH`，且每次启动重写 |

### 升级方式

按常规覆盖安装即可。首次启动会下载新的 `0.2.1-rc.2` 运行时（SHA-256 校验），执行既有的设置/凭据迁移，
并把旧设置文档放到 dsh 的导入位置。不会删除任何数据；旧运行时目录保留，便于回退。

> **关于设置导入的实测结论**：dsh 会把每个旧 section 导入到对应 entry，并按该 entry 的 schema 校验。
> 实测中 `locale` 与 `ui-onboarding` 正常导入；某个内容与当前 schema 不匹配的 section 会被跳过，并**原样留在
> `<DSH_HOME>/settings.yaml.imported`**（不会丢失）。若升级后发现某个自定义模型/供应商没出现，
> 在 Web UI「Settings → Models」里重新添加一次即可（此后会写入共享 profile，对所有项目生效）。
