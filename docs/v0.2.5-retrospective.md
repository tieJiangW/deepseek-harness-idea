## 2. 七轮现场问题：因果链与修复（最有价值的经验）

用户在真实 IDE 里连续报了 7 个现象。**每一个都不是"猜"出来的，而是靠日志/磁盘/独立探针定位**。按发现顺序：

| # | 现象 | 真因 | 修复 |
|---|---|---|---|
| 1 | 安装无任何过程反馈，不知道成没成 | `exec` 用 `waitFor` 把输出攒到结束；UI 只有一行静态文案 | `onPhase`/`onLine` 流式回调 + 进度条 + 每秒计时 + 心跳 + 取消 + 明确结果 |
| 2 | 点刷新一直读秒（54s） | ① `cleanLegacySharedRoot` 仍把 `<共享根>/profiles` 当 v0.1.2 遗留**递归删除**（上万个 node_modules 文件）；② 刷新跑了整套 `ensureHome` | 清理列表移除 `profiles` + 回归测试；新增轻量 `ensureProfileHome`；`mklink` 超时后**先杀进程再读流**；锁改 `tryLock(10s)` |
| 3 | 安装卡 149s（连心跳都没有） | 装/卸/修复跑在 `executeOnPooledThread`——IDE 刚重启时索引占满无界队列，任务**排队且不报错不打日志** | 改为插件自建单线程 daemon（`dsh-plugins-worker`），永不被"没人调度"卡住 |
| 4 | 卸载卡 61s（命令 1 秒就结束了） | 后台线程 `invokeLater` 的默认模态是 `NON_MODAL`，而设置页是**模态对话框** → 更新被推迟到对话框关闭 | 统一 `postUi()` = `invokeLater(block, ModalityState.any())` |
| 5 | 卸载 exit=1 | 运行中的 dsh 占用 `node_modules`，Windows 不允许删除被占用文件（add 只新增，故只有 remove 中招） | 降级为 **manifest 级移除**（dsh 按 `dsh.profile.bundles` 加载） |
| 6 | 删了重装报 `ERR_PNPM_VIRTUAL_STORE_DIR_MAX_LENGTH_DIFF` | `node_modules` 由**别的 pnpm 配置/版本**创建（dsh 自愈逻辑） | 读 `.modules.yaml` 的 `virtualStoreDirMaxLength` **对齐**；仍失败则把目录改名隔离并重试一次 |
| 7 | 装完还要手动去标题栏点重启 | dsh 只在启动时解析 profile（`patchReload: live` 只热重载 user patch 层） | `DshHarnessControl` + 设置页「立即重启 Harness」+ 通知 action |

### 2.1 通用教训（按价值排序）

1. **"没有日志"本身就是最强证据**：说明卡在第一个日志点之前 → 先怀疑**锁**与**外部进程 IO**，而不是继续优化遍历/磁盘。
2. **任何"串行化 + 可能卡住的外部进程"组合都必须给等待设上限**：`withLock` 无超时、`tryLock(900s)`、`readText()` 先于 `destroyForcibly()` —— 这三个都能把一次偶发变成永久卡死。
3. **后台 → 模态对话框 UI 必须显式 `ModalityState.any()`**：默认 `NON_MODAL` 会被推迟到对话框关闭（表现与"卡死"一模一样）。
4. **不要依赖 IDE 公共线程池做用户可感知的操作**：无界队列在索引期会把任务无限期挂着，且不抛错、不打日志。
5. **语义变更时要同步改"清理/迁移"白名单**：v0.2.5 把 `profiles` 升级为真源，但清理列表仍把它当遗留 → 删掉用户插件。**旧测试里的断言也可能是 bug 的背书**（当时那条 `assertFalse(exists(profiles))` 正是如此）。
6. **文本编辑 JSON 用结构化切分，不要正则**：正则版被单测当场抓出会混淆 `a` 与 `a-b`、并在删末项时留尾逗号（dsh 解析失败即 fail-loud）。
7. **失败要有"降级语义"而不是"重试到底"**：卸载走 manifest 兜底、`node_modules` 隔离重建、链接建不上就降级为项目独立 profile —— dsh 对 profile 加载 fail-loud，所以任何共享增强都**不能阻断启动**。
8. **发布资产必须"成对"同步**：CI 与本地构建的 zip **字节数可能相同、sha256 不同**；只按 size 跳过校验文件会导致用户下载运行时校验失败（见 §4.2）。
9. **泄露的凭据会被服务端撤销**：旧 GitHub PAT 直接 401、旧 Marketplace token 403 —— "我没改过"不等于"还有效"，排查第一步就是**验证凭据**而不是假定。
10. **会话历史是 append-only 的多帧 zstd**：直接 `zstdDecompressSync` 只解第一帧（得到几百字节 header），必须按 magic 扫描帧边界逐帧解压（见 §3.2）。

## 3. 可复用的排查手法（下次直接用）

### 3.1 三步定位"界面卡住"

1. **看日志有没有输出**：完全空白 → 卡在第一个日志点之前（锁/调度）；有前半段 → 卡在最后一条日志之后的那一步。
2. **命令是否已结束**：日志里出现 `ok` / `failed (exit=N)` 说明**命令早就结束了** → 问题在"后台→UI"的投递（模态/线程）。
3. **独立探针测真实路径**：把可疑的 JVM 调用写成单文件 `Probe.java`，用 JBR 直接跑（`java Probe.java`），逐项打耗时。本次用它证明了 junction 上的 `toRealPath` 2ms、`readString` 1ms、`createDirectories` 1ms —— **直接排除了磁盘**。

### 3.2 从会话历史里捞回凭据（本次用过）

- 会话数据：`<DSH_HOME>/sessions/<projectKey>/session*.jsonl.zstd`，**每行一个独立 zstd 帧**，帧间可能有填充字节。
- `zstdDecompressSync(整文件)` 只返回第一帧（≤ 几百字节），**看起来像"空会话"**。
- 正确姿势：按帧 magic `0xFD2FB528` + 帧头/块头结构扫描出 `[start,end)`，逐帧解压再拼接；本次扫出 **110,134 帧 / 178MB 文本**，才找到 token。
- 找到后**先用 `GET /user` 验证有效性**（本次两个 PAT 都是 401 → 已撤销），不要直接拿去推送。

### 3.3 重新打包后的产物自检（每次发版都做）

```powershell
# 解出 jar 内 plugin.xml，校验版本 / 兼容区间 / 更新说明首条
Expand-Archive build\distributions\deepseek-harness-idea-0.2.5.zip -DestinationPath $tmp -Force
# 期望：<version>0.2.5</version>；since-build=241 until-build=262.*；<h4>v0.2.5</h4> 在最前
```

## 4. 遗留与待改进（后续优化的直接依据）

### 4.1 必须在真实 IDE 手工确认（自动化覆盖不到）

| # | 待确认项 | 为什么自动化覆盖不了 |
|---|---|---|
| A1 | 安装/卸载/一键重启的**界面观感**（进度条、流式输出、按钮显隐） | 需要 IDE UI 与会话上下文 |
| A2 | 真实 JCEF 里的 composer 注入（v0.2.4 已用 CDP 在真实页面验证，但 Chromium 版本不同） | 依赖 JCEF 运行时 |
| A3 | 多项目并发（≤3）下共享 profile 的实际体验（切项目、装插件、重启） | 需要多个真实项目 |
| A4 | 卸载后重启 Harness，插件确实不再加载（含 manifest 兜底路径） | 需要真实 dsh 会话 |
| A5 | 升级到 v0.2.5 的迁移观感：日志出现 `migrated the project profile…`，`profiles-migrated/` 可回溯 | 需要真实旧 DSH_HOME |

### 4.2 发布流程（**P0，已发生一次真问题**）

1. **CI 与本地都会上传 runtime 资产**，而两者构建的 zip **字节数相同、sha256 不同** → 任何"只比大小"的跳过逻辑都会造成 zip/sha256 错配（本次已发生并修复）。
   - 短期：`scripts/release-v0.2.5.mjs` 已改为**以远端 `.sha256` 内容为准成对同步**并复核。
   - 建议（下一步）：**让资产只有一个来源** —— 二选一：① `build-release.yml` 负责构建并上传全部资产（本地只发布插件 zip 与正文）；② CI 只做构建验证，`upload-release-assets` 步骤加 `if: false`，由本地统一上传。后者更可控（离线也能发）。
2. **token 生命周期**：本次两个旧凭据都被服务端撤销（401/403）。建议固定流程：发布前**先验证**（`GET /user`、试调用一次只读接口）→ 发布 → **立即轮换**；`scripts/secret-audit.mjs` 的 `AUDIT_NEEDLES` 里同时纳入"是否仍出现在仓库/Release 正文"。
3. **正文被 CI 覆盖**：CI 的 `generate_release_notes` 会重写 body → 发布脚本已在上传后 PATCH 回中英正文；**顺序必须是"推 main → 推 tag → 等 CI → 最后 PATCH body"**。

### 4.3 代码与可观测性（P1）

1. **UI 层零自动化**：`DshPluginsConfigurable` 的按钮联动/状态机只靠人工。可引入 `BasePlatformTestCase` + 假 `DshHomeManager` 做平台级测试，或在 UI 里把"状态机"抽成纯类（`PluginsPageState`）单测。
2. **`DshHarnessControl` 的生命周期**：面板 `dispose` 注销、实例被平台复用（设置页 `createComponent` 会二次调用）。已修过"shutdown 后提交被拒"的坑，建议再加一条**集成测试**（模拟 dispose→reopen→restart）。
3. **诊断包**：日志已有 `ensureProfileHome` / `install(...)` / `refresh(...)` 关键点，但没有"一键导出诊断"（profile manifest + `.modules.yaml` + 最近 100 行日志 + 环境信息）。用户报障时能一次拿全。
4. **`DshProfileManifest` 的 JSON 读取器**是手写的（为免第三方依赖）：已知边界是"损坏输入降级为空"，建议补一条"超大 manifest（>1MB）"的用例，防止未来插件数量上升后解析变慢。
5. **`ensureProfileHome` 的超时语义**：锁超时返回 `null`，安装路径报 `PROFILE_BUSY` 让用户重试。可进一步：自动排队 + 进度提示（而不是让用户手动再点一次）。

### 4.4 产品能力（P2）

1. **插件市场目录**：目前只能手输包名。可对接 npm registry 搜索（`/-/v1/search?text=keywords:dsh-plugin`）做下拉候选，降低使用门槛。
2. **"已安装但需重启"标识**：现在靠成功文案提醒；可在表格里给"待生效"标记（对比 profile manifest mtime 与 dsh 进程启动时间）。
3. **插件更新检查**：`dsh plugin --profile web update <pkg>` 已可用，可加"检查更新"按钮。
4. **卸载彻底性**：manifest 兜底后 `node_modules` 有残留（无害）。可提供"清理残留"入口（需 Harness 停止时执行）。
5. **共享范围可视化**：设置页显示"哪些项目共享这个 profile"，减少"为什么 B 项目也装了"的困惑。

## 5. 本轮验证过的事实（避免未来重复试错）

| 事实 | 验证方式 |
|---|---|
| dsh 只在**启动时**解析 profile；`patchReload: live` 不重载 bundles | 装完不重启 → 列表有、运行时无该插件；重启后生效 |
| `dsh plugin remove` 在 dsh 运行时**稳定 exit=1** | 干净临时 profile：add/remove 都 0；运行中 profile：remove 恒 1 |
| `pnpm` 拒绝在"配置不一致"的 `node_modules` 上操作 | 用 `--config.virtual-store-dir-max-length=50` 造目录 → 默认配置 add 报 `VIRTUAL_STORE_DIR_MAX_LENGTH_DIFF`；对齐后成功 |
| junction 上的 JVM 文件操作都是毫秒级 | `Probe.java`：`toRealPath` 2ms / `readString` 1ms / `readAttributes` 19ms |
| 同一 profile 被两个 DSH_HOME 共享时数据仍隔离 | 两个 home + junction，并发启动：插件都加载、数据各写各家 |
| 迁移 187MB / 25388 文件的 profiles 只花 ~100ms | 日志 `ensureHome: profiles=…ms`（同卷 rename） |
| 泄露 token 会被服务端撤销 | 旧 PAT `GET /user` → 401；旧 perm token 上传 → 403 invalid |
